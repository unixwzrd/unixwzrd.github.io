Secrets Kit 1.2.0 - the "stop painting API keys on argv" release.

If you run agents from launchd (Hermes gateway, OpenClaw, your own daemon), you already know the trap: plists and shell snippets love to leak structure. `seckit run` resolves secrets in the parent, injects them into the child environment, and keeps values off the command line.

Also in this release:
- `seckit version --json` / `--info`
- CI coverage through Python 3.13
- clean cross-host workflow via encrypted export/import

iCloud Keychain sync via a native helper? We invested serious time; macOS has been handing back SIGKILL / policy walls while we wait on Apple.

The implementation is preserved in git (**`preserve/icloud-backend-as-of-2026-05-05`**) for when the OS stops acting like a bouncer who lost the guest list.

Title

Secrets Kit 1.2: launchd without the confession booth

Subtitle

Cleaner argv, `seckit run`, and a realistic take on iCloud Keychain

⸻

Body

There are two kinds of local security advice: the kind that fits in a tweet, and the kind that still works when you actually run software like a normal mammal.

Secrets Kit 1.2.0 leans toward the second.

The centerpiece is practical: `seckit run` resolves secrets from Keychain in the parent, puts them in the child environment, and avoids turning your command line into a billboard. That matters twice when you move to launchd, because plists and `ps` are not your friends.

If you run Hermes, OpenClaw, or anything else as a long-lived agent, wrap the real binary with `seckit run` and keep the plist boring, no secrets on disk or in argv.

Also shipped: friendlier tooling for operators (`seckit version --json` / `--info`), CI/release coverage that includes Python 3.13, and the same cross-host story that actually holds up: encrypted export and import.

On iCloud Keychain: we pushed hard on a native helper path; macOS has been killing it at launch with policy-style failures (SIGKILL / AMFI -413 territory) even when notarization looks fine. That work is preserved in git while we wait for something useful from Apple. Until then, export/import stays the honest sync story.
