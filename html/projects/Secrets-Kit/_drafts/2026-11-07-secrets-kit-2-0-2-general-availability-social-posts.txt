Secrets-Kit 2.0.2 is now generally available from Distributed Thinking Systems.

The free, open-source client keeps credentials on your machines, supplies selected values to applications and agents, and synchronizes between authorized peers on the same LAN segment without a hosted subscription. Version 2.0.2 introduces an encrypted SQLite synchronization workflow alongside the supported macOS Keychain backend.

For machines on separate networks, optional Remote Secret Sync carries destination-encrypted synchronization payloads. Your private encryption keys stay with you; we do not receive them and cannot decrypt those secret payloads. RSS costs US$5 per enrolled node/month, with a two-node minimum of US$10/month. Subscription enrollment is open, with no invitation or access code required.

This is not limited to AI agents. Database clients, scripts, scheduled jobs, and applications accepting environment variables can use selected credentials through seckit run. A receiving process gets plaintext and can expose it; credential management does not make an application trustworthy or replace backups.

Suggested title:
Secrets-Kit 2.0.2 released: free local credential storage and LAN sync, with optional paid RSS

Body:

We're Distributed Thinking Systems, the developers of Secrets Kit. Version 2.0.2 is now publicly available, and we'd welcome feedback from people managing credentials across workstations, home servers, and remote machines.

The client is free and open source. It keeps credentials locally and can give selected values to applications through seckit run, instead of copying passwords and API tokens into scripts and project files. Encrypted SQLite is the normal new-store and synchronization workflow; macOS Keychain remains a supported backend, but existing Keychain records do not automatically become synchronized SQLite records. The release supports macOS and glibc-based Linux.

Authorized peers on the same LAN segment can synchronize for free, with unlimited LAN connections and no hosted subscription. Each peer retains its own local storage protection. Discovery is not authorization, and synchronization is not a backup.

For peers on different networks, optional Remote Secret Sync (RSS) carries synchronization payloads encrypted for the destination. Customers retain their private encryption keys; we do not receive those keys and cannot decrypt the secret payloads. Sync messages pass through an in-memory delivery queue rather than a durable cloud secret archive. Account and operational metadata have separate retention rules, documented on the security and policy pages.

RSS is US$5 per enrolled node/month, minimum two nodes (US$10/month). A node is an enrolled Secrets Kit identity associated with an operating-system user, not each agent or application. Separate enrolled user identities on one physical machine can count separately. Subscription enrollment is open and does not need an invitation or access code. You do not need RSS to use the client or same-LAN synchronization.

This works with ordinary applications and scripts, not just agents. Hermes integration is optional. A process receiving a credential gets plaintext and can leak it; Secrets Kit is not a sandbox, protection against a compromised account, or a way to make an untrusted agent safe.
