LINKEDIN
==================================================

Secrets Kit 2.0.5 is released by Distributed Thinking Systems.

This update fixes a synchronization case that could leave a newly joined peer stuck, isolates installed tools from inherited Python and native-library environment settings, and adds more deliberate options for agent access and credential migration.

MCP remains read-only by default. An owner-approved policy can now allow writes to exact credential names within one fixed service and account. Metadata listing stays inside that scope, and the Hermes launcher is pinned to its approved policy. Write values can still be visible to the agent host or model; scoped permission is not a promise of secret invisibility.

For applications that need .env files, selected credential values can be exported into a protected dotenv file, with values rejected if the format cannot preserve them. Those files contain plaintext secrets, so protect them and verify the application's loader before switching over.

We've also added confirmation to local uninstall, kept credential stores and keys preserved by default, and clarified when RSS device revocation has actually released a slot for replacement. Uninstall does not cancel subscriptions or revoke devices.

The local-first client and authorized LAN synchronization remain free. Remote Secret Sync is optional for cross-network connections.

Title:
Secrets Kit 2.0.5: peer-sync fixes, opt-in scoped MCP writes, and selected credential export

Body:
Disclosure: We're Distributed Thinking Systems, the developers of Secrets Kit.

Version 2.0.5 is publicly released. Secrets Kit is a free local-first credential client for macOS and Linux, with encrypted peer synchronization and selected credentials supplied to applications through seckit run. Authorized LAN synchronization is free. Optional paid Remote Secret Sync (RSS) connects enrolled peers across networks.

The main changes:

- A fix for pending endpoint history that could leave a newly joined peer unable to synchronize. Each authorized peer receives the history in transaction order.
- Installed CLI, MCP, and Hermes helpers isolated from inherited Python/Conda and native-library environment settings.
- Opt-in MCP creation, revision-checked updates, and revision-checked deletion for exact credential names in one fixed, owner-approved service/account. Read-only remains the default. Metadata listing stays within scope, including duplicate credential names in different services.
- Selected-value dotenv exports for applications that require files. These contain plaintext credentials; the command rejects values it cannot preserve, and you need to verify the target loader before cutover. Placeholder exports remain available.
- Confirmation before local uninstall, with --yes for approved automation and the store/keys retained by default. Local uninstall doesn't cancel RSS billing or revoke devices.
- Clearer status for RSS revocation that is pending enforcement versus a slot ready for replacement.

The boundaries matter: MCP write arguments can be visible to the agent host or model. A scoped MCP policy is not isolation from another process with the same Unix user's authority. A process receiving a secret can expose it. Sync isn't a backup.

RSS remains optional at US$5 per paid node slot/month, with a two-slot minimum. No subscription is required for local use or LAN sync.
