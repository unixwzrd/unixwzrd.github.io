UnicodeFix v2.1.0 no longer needs ExifTool for image cleanup. I replaced the external backend with built-in PNG, JPEG, and WebP container handling, so the normal Python installation includes the cleanup runtime. One less executable to install and track down on PATH.

The important part is what happens to the image. Cleanup preserves its coding data rather than recompressing it, retains rendering metadata and animation, and verifies protected data before publishing a separate output file. Recognized C2PA provenance still takes an explicit request to remove.

The format boundary is narrower and explicit: TIFF, HEIF, AVIF, GIF, and BMP are audit-only in this release. This is supported metadata cleanup, not a claim that every hidden payload or pixel watermark has disappeared. Python 3.11+ and Pillow 13.x are the current baseline.

Suggested title:
UnicodeFix 2.1: built-in PNG/JPEG/WebP metadata cleanup, no ExifTool required

Body:

I maintain UnicodeFix, a local text and image audit/cleanup tool. In v2.1.0 I replaced the ExifTool subprocess backend with built-in container writers for PNG, JPEG, and WebP. The normal Python installation now includes the image cleanup runtime.

The writers retain image coding data instead of decoding and re-encoding the pixels. ICC profiles, orientation, supported color-space fields, and animation frames/timing are preserved, with protected-block hashes and rendering metadata checked before the separate output file is published.

The usual commands still work:

    cleanup-text --report --metrics photo.jpg
    cleanup-text --dry-run photo.jpg
    cleanup-text photo.jpg

Those audit, preview, or write photo.clean.jpg respectively. The dedicated cleanup-image command remains audit-only unless a cleanup flag is supplied.

There are deliberate limits: TIFF, HEIF, AVIF, GIF, and BMP are audit-only in this release, input files are capped at 256 MiB, and unsupported metadata variants can prevent writing even in a normally writable format. C2PA removal must be explicit. Unknown blocks are retained, signatures are not validated, and this is not a pixel-watermark remover.

Python 3.11+ and Pillow 13.x are required. The article covers the changes and the image-report schema update; the repository has the implementation and format guide. Feedback on real-world container edge cases would be welcome.
