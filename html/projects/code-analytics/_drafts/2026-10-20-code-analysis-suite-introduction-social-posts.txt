LINKEDIN
==================================================

A long function is a reason to investigate, not permission to redesign the application. Before changing a codebase, I want evidence about ownership, dependencies, state, and the likely impact of the change.

Code Analysis Suite turns source structure into saved evidence for that review: symbols, dependencies, complexity, contracts, duplication, and change/test relationships, with capability differences documented for Python, JavaScript/JSX, and Ruby.

The retained JSON report can drive tables, diagrams, comparisons, and review artifacts without another source scan. The analysis is local, static scans do not execute the target application, and proposals do not rewrite source.

The CLI analysis and artifact-generation workflows are working. The local WebUI, built with LocalOps UI Kit components, is still in beta and has rough edges I am testing and fixing. I would particularly welcome feedback on where it helps an investigation and where it gets in the way.

There are also nine Fawlty Towers-inspired tutorial investigations with supplied evidence, so you can try it before pointing it at your own project.

Body:

I'm the author of Code Analysis Suite. It is an MIT-licensed beta candidate for understanding code structure and reviewing proposed changes, not an automatic refactoring tool.

The analysis covers symbols, dependencies, complexity, duplication, state/effects, and change/test evidence. Python has the broadest coverage, including contracts and dictionary shapes. JavaScript/JSX and Ruby have optional parser frontends with narrower capabilities. TypeScript/TSX is not supported, and missing or partial evidence stays explicit.

The core artifact is a validated JSON report with source locations/hashes, provider states, diagnostics, and stable evidence IDs. CLI queries, tables, diagrams, and comparisons work from retained evidence without another source scan. Static scans do not import or execute the target application, and the tool does not rewrite source. Profiling and coverage execution are separate, explicitly authorized workflows.

The CLI and artifact generation are working. The loopback WebUI uses LocalOps UI Kit and is still rough in places; I am testing and fixing it now. I would appreciate feedback on whether you can follow a finding into the relevant evidence/source, understand provider limitations, and navigate without losing the thread.

If you would rather start with sample code, the checkout has nine Fawlty Towers-inspired investigations across Python, JavaScript, and Ruby, with saved evidence, optional hints, and separate solutions. You do not have to run the sample applications to investigate their saved reports.

Python 3.12+ is required. Install from the source repository; this is not a PyPI-release announcement. Reports can contain private source details, so please use a minimal synthetic reproduction rather than posting a proprietary workspace.
