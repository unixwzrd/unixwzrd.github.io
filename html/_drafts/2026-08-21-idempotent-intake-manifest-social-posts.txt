The first import is the easy one. The rerun tells you whether the design is any good.

As a hands-on follow-up to my deterministic intake article, I built a deliberately small Python and SQLite example. It gives text sources stable identities, hashes their contents, records provenance, and distinguishes new, unchanged, and changed sources without creating duplicate rows.

It does not summarize documents, create embeddings, or decide what belongs in memory. That is the point. This exercise stops at the smallest contract I want to trust before a model or retrieval system enters the picture.

The runnable example uses only the Python standard library.

Title:
Hands-On: Build an Idempotent Intake Manifest

Subtitle:
A small Python and SQLite exercise for proving that ordinary reruns do not create duplicate source records.

Body:

The first import only proves that a pipeline can create data. The second and third runs show whether it respects the data and identity already there.

This hands-on follow-up uses the Python standard library and SQLite to build a small local manifest. It assigns stable source identities, fingerprints contents, records provenance, and reports whether each source is new, unchanged, or changed.

It deliberately stops before summaries, embeddings, human review, and retrieval policy. Those are different stages with different failure modes.
