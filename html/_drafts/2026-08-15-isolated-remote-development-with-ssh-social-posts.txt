Remote development does not have to begin with a remote machine.

A second account on the same Mac is enough to separate the runtime home directory, shell environment, packages, editor server, and user-level services from my normal development account. Once that works, moving the same setup to another Mac, a Linux host, or a VPS mostly changes the SSH hostname.

This hands-on tutorial starts with authorized_keys and reusable SSH aliases, then walks through remote workspaces in VS Code, Cursor, and Windsurf. It also shows how I attach debugpy to an existing Python process through an SSH tunnel without exposing the debugger port to the LAN or Internet.

Hands-On: Isolated Remote Development with SSH

Subtitle:
Build one understandable SSH workflow for another account on the same Mac, a remote machine, or a VPS.

Body:

Remote development becomes much easier to troubleshoot when the editor is a client of an SSH connection I have already tested.

This tutorial starts with a dedicated account, an Ed25519 public key, authorized_keys permissions, and reusable aliases in ~/.ssh/config. It then uses that foundation for remote workspaces in VS Code-style editors and for attaching debugpy to an existing Python process through an SSH tunnel.

The same procedure works locally under another user, across a LAN, or on a VPS. The target changes; the authentication and debugging boundaries remain recognizable.
