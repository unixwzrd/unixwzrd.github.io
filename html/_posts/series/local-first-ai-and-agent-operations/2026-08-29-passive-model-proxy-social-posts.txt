I reached a point where inspecting the JSON request was no longer enough. The messages and tools looked right, but the answer still made me wonder what the model had actually been asked.

The missing view was the rendered prompt. A chat template can duplicate a tool result, mishandle a role boundary, omit a generation marker, or carry too much history forward while the structured request still looks perfectly reasonable.

Part 6 of Local First AI and Agent Operations explains how I use a passive model proxy to correlate the raw request, rendered prompt, and response without letting the diagnostic path rewrite the exchange. It also covers streaming reconstruction, client disconnects, rotation behavior, and why useful prompt diagnostics must be treated as sensitive incident evidence.

A separate Hands-On companion follows on August 31 with a standard-library Python proxy, deterministic fake endpoint, and six executable privacy and byte-preservation canaries.

Title:
A Passive Model Proxy as an AI Debugging Instrument

Subtitle:
Why the structured request is only one view of a model exchange, and how I inspect the rendered prompt without changing the evidence.

Body:

An OpenAI-compatible request contains messages, tools, options, and perhaps multimodal content. The model does not consume that JSON envelope directly. Its chat template converts the request into the token-bearing prompt, and that transformation can fail while the original request still looks correct.

Part 6 explains the passive proxy boundary I use to correlate the raw request, rendered prompt, and response. The article covers streaming reconstruction, client disconnect classification, timed numbered log rotation, sensitive diagnostic retention, and the proposed separation between detailed incident evidence and content-free routine metrics.

The companion article follows on August 31 with complete readable source for a standard-library Python proxy, deterministic fake endpoint, and six regression canaries covering exact body preservation, private marker exclusion, restrictive file permissions, sanitized upstream failure, credential-bearing URL rejection, and explicit remote opt-in.
