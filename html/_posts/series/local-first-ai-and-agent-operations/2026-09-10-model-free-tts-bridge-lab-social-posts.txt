You do not need a cloned voice, a GPU, or a network provider to test the operational boundary around a TTS bridge.

Hands-On 9A packages the useful part as a five-file, standard-library Python lab. It generates a short tone and invented transcript, starts a teaching bridge and fake OpenAI-compatible upstream on loopback, and checks the happy path and the failure cases.

The sixteen-condition run proves request translation, case-insensitive alias selection, paired reference paths, explicit OGG-to-WAV fallback, byte-preserved returned media, bridge-versus-upstream health, bounded timeout behavior, operational-event input redaction, upstream loss, and cleanup.

The package includes four regression tests and collapsed source viewers, so readers can inspect everything before downloading it. It deliberately proves no voice identity, consent, model quality, provider compatibility, or production performance.

A five-file standard-library Python lab for request translation, paired references, format fallback, layered health, bounded failures, redaction, and cleanup.

Body:

The main Part 9 article separates the speech bridge from the inference engine behind it. This Hands-On companion turns that boundary into something you can run without a model, GPU, provider account, or real voice.

The lab generates a short tone and invented matching transcript, starts a teaching bridge and fake OpenAI-compatible upstream on loopback, and runs sixteen bounded acceptance checks. It verifies alias and paired-reference selection, explicit OGG-to-WAV fallback, returned bytes, independent bridge and upstream health, timeout and outage behavior, operational-event redaction, and complete cleanup.

The package uses only the Python standard library and includes four regressions. It is a protocol and failure-behavior lab, not a voice-quality demonstration.
