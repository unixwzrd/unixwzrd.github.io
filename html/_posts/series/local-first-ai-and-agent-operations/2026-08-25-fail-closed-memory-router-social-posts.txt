Filtering a private memory out of the final response is not enough if the scorer, logger, cache, or debugger already received it.

This Hands-On companion to Part 3 builds a small fail-closed memory router in standard-library Python. It uses invented general and private banks, three bounded context outcomes, bank-tagged results, and a deliberately ordinary token-overlap scorer.

The important part is the ordering. Authorization constructs the candidate set before deduplication and ranking. A recording-scorer canary proves that excluded private content never reaches the scorer, while six more tests cover write refusal, bank isolation, unknown-context fallback, merged private recall, duplicate handling, and rebuild removal.

Both complete files are readable and downloadable from the article.

Hands-On: Build a Fail-Closed Memory Router

Subtitle:
A runnable Python example that constructs the authorized candidate set before relevance ranking begins.

Body:

It is easy to make a retrieval demonstration look safe by removing protected results from the final list. That does not prove the scorer, logger, cache, trace, or debugger never received the protected content.

This companion article builds a deliberately small router using only the Python standard library. Unknown contexts can read general material but cannot write, recognized general contexts remain in the general bank, and recognized private contexts can combine bank-tagged general and private results.

Seven canaries test the boundary, including a recording scorer that proves private content never reaches ranking during a general query. The article includes the complete utility and test suite as readable, downloadable files.
