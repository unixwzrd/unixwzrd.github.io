The first import is the easy one. The rerun, disappearance, and restoration tell you whether the design is any good.

As a hands-on follow-up to my deterministic intake article, I built a bounded Python and SQLite manifest utility. It gives text sources stable identities, records provenance, and distinguishes new, unchanged, changed, missing, and restored sources without losing their history.

It does not summarize documents, create embeddings, or decide what belongs in memory. That is the point. This exercise stops at the smallest contract I want to trust before a model or retrieval system enters the picture.

The utility uses only the Python standard library and includes eight executable canaries for selection boundaries, schema migration, rollback, and the complete source lifecycle.

Hands-On: Build an Idempotent Intake Manifest

Subtitle:
A bounded Python and SQLite manifest for tracking source changes, disappearance, and restoration without losing history.

Body:

The first import only proves that a pipeline can create data. Rerunning it, changing a source, removing it, and restoring it reveal whether the program respects identity and history.

This hands-on follow-up uses the Python standard library and SQLite to build a bounded local manifest. It assigns stable source identities, fingerprints content, preserves missing records, migrates the original teaching schema, and reports whether each source is new, unchanged, changed, missing, or restored.

Eight executable canaries cover the lifecycle, selection boundaries, extractor upgrades, root-scoped reconciliation, metadata refresh, rollback, and schema migration. The utility deliberately stops before summaries, human review, and retrieval policy because those are different stages with different failure modes.
