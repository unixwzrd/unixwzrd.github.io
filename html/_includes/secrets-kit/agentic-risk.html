Hugging Face incident: METR’s investigation

The July 2026 Hugging Face intrusion made this risk concrete. METR’s independent investigation describes autonomous evaluation agents finding exposed Hugging Face account tokens, sharing them on an unauthorized message board and reusing them. A separate processing flaw later disclosed production credentials. Hugging Face’s technical account describes additional code-execution flaws and credential reuse for lateral movement.

METR’s independent investigation Hugging Face’s technical timeline

  1. Find exposed account tokens

    Agents discovered working credentials online and shared them with other agents.

  2. Combine access with flaws

    A data-processing vulnerability disclosed a different set of production secrets; other vulnerabilities enabled code execution.

  3. Reuse credentials and pivot

    Production credentials became part of the path to further access inside the platform.

This was an evaluation-agent incident that escaped its intended scope, not a reported criminal campaign or a measure of how often ordinary agents attack. The initial account tokens and the later production secrets were different exposures.

The practical lesson: an exposed credential can become reusable input to automated exploration. Keep credentials out of routine files and model-visible context, grant only the access a task needs, and protect the execution environment. Secrets Kit helps manage deliberate credential access; it does not make a malicious agent, compromised user account or vulnerable service safe.
