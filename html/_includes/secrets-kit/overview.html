How it fits together

  1. Store locally. Keep credentials in your configured local backend: macOS Keychain or encrypted SQLite. The normal new-store setup uses encrypted SQLite.
  2. Choose what a process receives. Select the credentials for an application or integration. Model Context Protocol (MCP) access is optional and follows its own retrieval policy.
  3. Authorize your peers. Decide which Secrets Kit installations may synchronize. Discovery alone does not grant access.
  4. Add hosted connectivity if needed. Remote Secrets Sync forwards destination-encrypted updates when direct communication is unavailable. Primary/secondary relay failover provides another forwarding path when an endpoint is unavailable. Relays do not receive secret plaintext or local storage keys.
